# 海报与封面设计

适用于活动海报、产品宣传、文章封面、信息卡片和已有图片改版。先把信息组织好，再调用现有 `mcp__yomi_image__generate_image` 或 `mcp__yomi_image__edit_image`。不要只输出一串风格形容词。

## 工作方式

1. **判断目的与受众**：这张图让谁看到、记住什么、采取什么行动。辨认发布渠道、比例、必须出现的文案及参考图。
2. **补足缺项**：次要信息采用合理假设并简短说明，例如“按手机端竖版、首次接触品牌的读者设计”。缺少日期、价格、地址等事实，不编造；用占位符或省略。只有缺项会改变核心方向、造成事实错误，或涉及工具强制批准时才提问。不要每次都发问卷或要求审批。
3. **给出一个主方案**：用 3–6 行说明目的/受众、文案层级、版式、配色字体、主体与留白。用户明确要比较时才给 2–3 个方向。用户已要求生成或编辑时，方案说明后直接执行授权范围内的工具调用，不把“方案确认”变成固定关卡。
4. **选择制作方式并执行**：短文案可直接生成完整海报；长文案、精确中文、多处日期数字或严格品牌排版，优先生成主视觉，再以 HTML/SVG 叠加精确文字。已有图按需编辑，避免无意义重做。
5. **自查并交付**：说明产物、关键假设和必要的使用方式。能检查图片时检查实际结果；无法检查时明确哪些项尚未验证，不宣称已经视觉验收。

## 设计决策

- **目的**：只保留一个主要动作，如报名、了解产品、打开文章。行动入口不与标题抢视觉权重。
- **受众**：按阅读场景确定密度。手机缩略图先保证标题与主体；信息海报再兼顾正文细节。
- **文案层级**：一级是唯一主标题；二级是利益点或副标题；三级是日期、地点、说明与行动入口。保留用户事实与关键措辞，改写重要文案时明示。
- **布局**：从 [5 种版式](references/layouts.md) 选一种，建立对齐线；用 [版式一览](assets/layouts.svg) 对照。主体、文字、标识各有稳定区域。
- **留白**：预留四周安全边距约 5%–8%，文本区内避免复杂纹理、高反差边缘和主体关键细节。留白是连续可读区域，不只是背景看起来“空”。
- **字体与配色**：参考 [配色与字体](references/palettes-type.md)，默认一套字体家族、两种字重，最多两套字体；背景/主色/强调色有明确分工，先保证可读性。
- **参考**：用户参考图只用于分析网格、层级、留白与色彩关系，再重新组织构图；不要复刻标识、独特插画或具体作品。无授权时使用原创图形、自己生成的视觉或用户有权使用的素材，不下载外部版权素材充当成品。

## 图像工具与参数

- 使用现有工具，不虚构新工具或本地渲染能力。常规默认 `gpt-image-2.5`，仅指定 `aspect_ratio` 时使用该比例的默认尺寸，通常省略 `size`；不要自行把比例换成像素尺寸。
- 用户显式指定 `size` 时，尺寸优先于比例；二者冲突时以尺寸为准，并在需要时简短说明。保留用户指定的模型与质量，遵守工具实际支持的参数。
- 不因“更清晰”“更高级”擅自升级到 `gpt-image-2.5-sunburst`。明确 2K/4K 或长边超过 2048 的尺寸可能触发 Sunburst 路由；任何 Sunburst 调用都须获得本次交互的明确批准。批准已覆盖同一调用时无需重复询问；未获批准时先完成方案与提示词，再提出必要确认。
- `edit_image` 使用实际存在的本地输入图片路径；蒙版须符合工具规定。提示词明确保留项、修改项和文字禁入区域。
- 用户要求多张互不依赖的图片时，文生图优先调用 `mcp__yomi_image__generate_images`；图像编辑优先调用 `mcp__yomi_image__edit_images`。尤其是先用一张参考图确认风格、再处理其余参考图时：首张可单独调用 `edit_image` 定稿，风格确认后必须把剩余独立编辑项合并到一次 `edit_images` 调用，不要连续调用多次 `edit_image`。将全部独立任务放入tasks一次并发提交，插件不设固定数量或并发上限。每项参数与对应单图工具相同，可设置output_mode。只有需要上一项结果才能设计下一项时才顺序执行。批量含Sunburst须整批提交前批准；各项分别计费，不自动重试。失败时报告具体编号，保留成功项；再次付费调用应有用户授权。
- 提示词写清主体位置、画面比例、文字区域、留白边界、配色和禁止出现的杂字。示例见 [提示词配方](references/prompt-recipes.md)。

## 长文案与精确叠字

使用本技能目录下的 [HTML 模板](templates/poster.html)，按选定版式调整结构、颜色和文本；也可制作可编辑 SVG。以上链接均相对于本技能目录。不要覆盖原模板来保存某次用户作品；将成品存到用户工作区中合适的位置。

先生成无文字主视觉，明确标题、正文与页脚各需的平整低细节背景。主体不得侵入文字区域，尤其不要把人脸、产品标签或高亮边缘放在标题背后。随后用真实 HTML/SVG 文字叠加，核对断行、溢出和数字。长内容优先精简或拆页，不能靠无限缩字号塞入画面。

没有浏览器环境时，可交付 HTML/SVG：HTML 可由用户打开后打印、截图或另行导出。不要宣称已渲染 PNG 或已自动导出。只有存在可用浏览器工具时才自动导出，并检查输出；不要为了导出擅自安装浏览器或启动替代服务。

## 交付前自查

- 目的和主标题能否在缩略图中迅速辨认？是否只有一个视觉中心？
- 标题、副标题、说明、行动入口的顺序是否清楚？事实、日期、数字和原文是否准确？
- 对齐线、边距和行距是否一致？是否有拥挤、遮挡、溢出或关键元素贴边？
- 图片背景的文字区是否低细节、对比稳定？字号与配色是否适合实际阅读尺寸？
- 是否使用可合法使用的字体与素材？参考是否已转化为原创构图？
- 模型、比例、显式尺寸与批准范围是否吻合？交付说明是否准确反映实际生成及验证状态？
